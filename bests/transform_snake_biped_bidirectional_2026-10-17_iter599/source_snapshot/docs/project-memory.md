# Zbot 项目永久记忆

更新日期：2026-10-03。本文记录开发约定、代码现状和验证边界；后续开发先阅读本文和 [坐标系约定](zbot-coordinate-system.md)。参数是当前实验值，不是已经验证的最优值。

## 机器人和坐标定义

- Zbot 为约 0.3 m 高的六自由度模块化双足机器人。当前资产包含 12 个有质量的刚体、6 个铰链，浮动根节点是 `foot_0`，任务速度参考点是 `base`，两者不能混用。
- 世界重力加速度是 `(0, 0, -9.81) m/s²`；用于构造方向的单位重力向量是 `g=(0,0,-1)`。向上方向是 `u=-g`，不能将重力加速度与单位方向混为一谈。
- 将 base 局部 `+Z` 轴旋转到世界坐标，记为 `z_b_w`。前进方向为 `f=normalize(g × z_b_w)`；左方向为 `l=normalize(f × g)`。两条轴均水平，模块 Z 轴倾斜时也不能直接用它代表左右方向。
- `g × f` 指向右侧；交换叉乘顺序会反转左右。先水平投影模块 Z 轴再做叉乘，与直接叉乘的前向方向等价。
- `(f,l,u)` 是标准右手正交基；当前代码返回 `(f,l,g)`，由于第三轴向下，这个三轴组合是左手基。每个叉乘遵循右手定则，不代表最终组合也一定是右手基。
- 模块 Z 轴接近重力方向时叉乘退化。`clamp_min` 只能防止除零，不能恢复有效方向；后续需检查终止与退化处理。

## 指令和速度测量

- 当前前后指令范围为 ±0.25 m/s，侧向 ±0.12 m/s，偏航 ±0.5 rad/s；10% 为站立指令，5–10 s 重采样一次。全方位指方向覆盖，不能套用 G1 的速度规模。
- `base_lin_vel` 必须使用第三个身体模块 `base` 的即时 link 原点线速度，不能使用浮动根节点 `foot_0`；先用 `base` 姿态变换到 Base 身体坐标，再与身体坐标中定义的 `forward` 轴做点积。角速度使用 `base` 模块 link 角速度，EMA 已移除。Root 仅是 MJCF 浮动关节参考，不是 Zbot 速度测量参考。
- 观测、跟踪奖励、命令误差和箭头应共享同一坐标。命令积分已改用 Zbot 的 `f/l`，但 `commanded_displacement_w` 当前不进入速度跟踪奖励，所以修复积分本身不能证明奖励或步态改善。
- 目前偏航测量沿 `g` 为正，即从上方看顺时针为正；G1 通常沿向上轴为正。开发时必须明确该符号差异。不能仅因为三轴正交，就宣称偏航约定与 G1 一致。
- MJLab command 的 world-frame、heading、初始速度写入逻辑采用标准根部坐标。当前这些功能关闭；启用前必须适配 Zbot，不能直接继承。

## 奖励与训练经验

- 小速度指令下，原始指数奖励 `exp(-error²/std²)` 可让静止获得高分。现改为相对静止基线：`max(0,(score-baseline)/(1-baseline))`，分母下限 `1e-4`。线速度指令范数或角速度绝对值不超过 0.02 时对应跟踪奖励为零。
- 当前线/角速度权重各为 2；标准差分别为 0.3 m/s、0.5 rad/s。此前更紧容差被放宽，但未通过长期训练证实效果；奖励截断区可能没有有效学习信号。
- 当前临时实验已将两个速度项改为非指数、非指令跟踪目标：线速度项直接奖励 `forward` 速度并惩罚 `left/gravity` 方向速度平方；角速度项惩罚三轴角速度平方。恢复 command tracking 前，必须明确标记并比较该实验结果。
- 线速度临时目标现已拆分：`track_linear_velocity` 只返回非负 `forward` 分量；`lateral_velocity` 单独惩罚 `left/gravity` 分量。这样前进奖励指标不会被侧向/竖直惩罚变成负值。
- 当前直接前进速度奖励权重为 `5.0`，用于提高前进目标相对动作和接触正则的影响；调整后必须重新训练并观察是否诱发跌倒或高频摆动。
- 周期踏步任务的 `upright` 是连续稳定引导，不是跌倒判定；当前权重从 `1.0` 降为 `0.2`，因为 `fallen` termination 已负责真正跌倒，避免姿态项压制相位踏步学习。
- `pose` 已由正奖励改为小惩罚：`-0.05 * mean((q-q_default)²)/0.5²`。默认姿态为零，避免静止持续拿满姿态奖励。
- 存活项权重为 +0.2；当前跌倒/终止使用一次性 -20 强惩罚，防止早死成为策略选择。奖励管理器按 `step_dt` 积分，终止函数除以 `step_dt` 保持离散惩罚；若总奖励再次长期贴近 -20，必须查看终止频率和各项奖励贡献，而不是单独继续加大惩罚。
- 当前奖励并非与 G1 完全一致：姿态、速度基线、存活和终止项已定制；足端摆动、软着地、自碰撞实现也有差异。
- 观察到早期迈步、后期静止，以及命令变化后短暂动作；这些是用户观察。EMA 是曾发现的实现差异，尚不能证明它是上述行为的根因。

## 终止与尚未解决的问题

- 原 `fallen` 读取自碰撞传感器，导致脚碰撞同时计入 Fallen 和 Self Collision；该重复判定已移除。
- 临时直接前进实验中，Self Collision 不应终止 episode；当前仅保留低权重碰撞成本，避免策略通过碰撞早死形成局部最优。恢复碰撞终止前必须证明传感器不会把正常模块接触当作致命碰撞。
- 临时直接前进目标可能被高频内部关节摆动或模块互撞利用；因此当前加入 joint velocity 正则，并提高可恢复的自碰撞持续惩罚。若仍出现循环摆动，应记录各奖励项、base 速度和关节速度后再调权重，不能仅凭总奖励判断。
- 当前临时直接前进实验已移除 `upright` 奖励项；跌倒约束仅由 `fallen` termination 和终止惩罚负责。恢复姿态奖励前需重新评估其坐标定义和权重。
- 直接前进实验中角速度惩罚曾重复叠加（主项 + body angular velocity + angular momentum），导致机器人无法运动；当前三个角速度相关项权重全部为 0，暂时完全关闭。恢复角速度约束前必须重新检查重复惩罚。
- 当前 `fallen` 使用 base 高度 <0.22 m、模块 Z 轴世界竖直分量绝对值 >0.75，以及世界 Y 偏移 >0.5 m。模块 Z 检测不能覆盖所有跌倒方向；世界 Y 边界也会限制正常侧移，二者仍需审查。
- 自碰撞 termination 阈值当前为 1 N，奖励阈值为 10 N；轻微碰撞可立即终止却没有对应自碰撞奖励，需核对是否过敏。
- `upright` 已改用 base 模块局部 Z 轴的世界竖直分量作为倾斜量；Zbot 直立时该轴应平行地面。不能使用 G1 的 base 局部重力 XY 测试，因为 Zbot base 局部 Z 不是竖直轴。`body_ang_vel` 仍取原 base XY，亦未完成运动坐标适配。
- 名为 `angular_momentum` 的项当前实际是 base 角速度平方代理，不是全身角动量，不能视为 G1 的等价项。

## 物理资产与可视化

- 默认 `robot_geometry_inertia.xml` 保留来源质量，以均匀网格体积估算惯量；不是实测硬件惯量。当前总质量约 3.00504 kg，每刚体约 0.25042 kg。
- ±2.4 rad 限位、0.05 阻尼、0.0001 armature 是开发中加入的仿真参数，尚无硬件标定证据；正质量、正惯量和成功编译不等于符合实机定义。
- 足端使用 MJLab `TerrainHeightSensorCfg`，在两个 foot body 上各配置半径 0.03 m 的环形射线，显示地面命中点。body frame 高度与实际脚底 clearance 可能有偏移，不能当作已校准足底 site。
- 箭头起点沿世界 +Z 抬高 0.12 m，不能沿 base 局部 Z 偏移。长度按各命令范围归一化，显示比例 0.25；归一化显示不改变物理指令或奖励。
- `visualize.sh` 使用 MJLab 平地 checker 材质与 directional sun；展示地面在独立模型中添加。
- 训练保持 headless；`preview_training.sh` 后台轮询并重启独立 Viewer 加载新 checkpoint，不录视频。实际持续刷新可靠性仍需进程级验证。

## 验证规则和入口

- `./scripts/python.sh -m zbot_rl_mjlab.cli validate-robot`：资产基础检查。
- `./smoke.sh --num-envs 1 --steps 8 --device cpu`：有限值和接口检查。
- `./scripts/python.sh -m ruff check src`、`git diff --check`：静态检查。
- smoke 成功不证明训练收敛、真实跌倒检测、速度跟踪或 Viewer 视觉正确。需要固定前进/侧移/旋转命令，对照即时速度、位移差分、各奖励项与终止原因，并做不同偏航/倾斜姿态测试。
- 已运行训练进程不会自动读取源码改动；需重启。checkpoint 恢复可保留旧任务卡参数，实验必须记录实际生效配置，不能只读默认值。

主要实现：`src/zbot_rl_mjlab/mdp.py`、`env_cfg.py`、`task_card.py`、`robot.py`、`visualize.py`，以及 `preview_training.sh`。本次只保存知识，不修改训练行为。

## 当前踏步/行走仿真配置：对齐 G1 平地

物理时间步 0.005 s（200 Hz），decimation=4，策略周期 0.02 s（50 Hz）；Newton iterations=10、ls_iterations=20、ccd_iterations=50；njmax=300、nconmax=None、contact_sensor_maxmatch=64。两任务共享配置，踏步频率现在按每个 episode 在 0.5–2.0 Hz 之间采样，相位按真实仿真时间计算。修改于 2026-10-03；需重启训练生效。

实体碰撞已按 G1 profile 对齐：足端 `condim=3`、摩擦首系数 `0.6`；其他碰撞几何 `condim=1`；所有 Zbot 几何的 `margin=0`、`gap=0`，默认 `solref/solimp` 与 MuJoCo/G1 一致。运行时 `get_spec()` 和两个 MJCF 文件保持一致。自碰撞是否开启仍由接触排除表和任务传感器决定，不能仅从 condim 推断。
